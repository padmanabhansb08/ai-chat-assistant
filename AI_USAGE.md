## 6. 🧠 Engineering decisions

### Architecture

```
presentation  (screens, widgets, blocs)
      │  depends on
      ▼
domain        (entities, repository interfaces, use cases)
      ▲  implemented by
      │
data          (data sources, models, repository implementations)
```

- Blocs depend on **use cases only**, never on data sources or UI. Everything is wired in one place, `core/di/injection.dart` (get_it).
- The data layer throws typed **`Failure`** subclasses (network, timeout, auth, rate limit, invalid response, server, config, storage). HTTP status codes are mapped in **one function**, `core/network/http_guard.dart`. Blocs catch `Failure` and put it in state.

### Bloc design

| Decision | Why |
|---|---|
| `ChatState` is **one class with a status enum** (initial / loading / sending / success / error) | The message list stays on screen during loading and errors. Separate subclasses would wipe it. |
| `droppable()` on `ChatMessageSent`, plus an `isSending` guard | Duplicate requests are blocked **inside the Bloc**, not only by disabling the button. |
| `sequential()` for `ConversationBloc` writes | Creates, deletes and reloads never interleave. |
| `ConversationOpened` / `ConversationClosed` with `openedId` in state | The Bloc owns "which chat is open"; the screen only reacts to state. |
| Theme handled by `SettingsBloc` (`SettingsThemeChanged`) with a Flutter-free `AppThemeMode` enum | The domain layer stays free of UI types. |
| `ConversationBloc` / `SettingsBloc` use sealed state subclasses | Matches the states the brief lists. |

### Data and providers

- **Provider-agnostic AI:** one `AiRemoteDataSource` interface with two implementations: OpenAI-compatible (`/chat/completions`) and Gemini (`generateContent`), chosen by `ProviderType`. Base URL, API key and model are user-configured and persisted; **nothing is hardcoded**. Presets only pre-fill the form.
- **SQLite over Hive:** messages belong to conversations, so a relational schema fits: `ON DELETE CASCADE`, an index on `(conversation_id, timestamp)`, and a transaction that inserts a message and bumps `updated_at` together.
- **Resilient sending:** the user message is saved **before** the network call, so it survives failures and offline use. **Retry** (`ChatRetried`) re-sends it with `persistUserMessage: false`, so history is never duplicated.

### Security

- The API key is stored with **`flutter_secure_storage`**, never in SQLite or SharedPreferences.
- Gemini auth uses an **`x-goog-api-key` header**, so the key never appears in a URL or log.
- Plain-HTTP traffic (for local servers like LM Studio) is allowed **in the debug manifest only**; release builds block it.
- No secrets are committed. A scan of the repository found only fake test values.

### Bonus features chosen

1. **Markdown rendering** of AI replies (user messages stay plain text)
2. **Dark mode** (System / Light / Dark), persisted
